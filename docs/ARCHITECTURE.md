# Architecture (V0.1)

BibVault keeps two layers:

- User-facing files are named from the BibTeX citation key: `papers/{citation_key}.pdf`.
- SQLite stores the publication identity. A DOI becomes `doi:...`, an arXiv id becomes `arxiv:...`, a URL becomes `url:...`, and a record with none of those becomes `internal:...`. The citation key is never that identity. A `doi.org` link in `url` counts as a DOI, and an arXiv DOI (`10.48550/arXiv.*`) maps to the same `arxiv:` identity as the bare eprint.

`manifest.json` is rewritten from SQLite after each fetch or sync.

## Pipeline

1. Parse BibTeX with `bibtexparser` 1.4, with `@string` macros and `crossref` inheritance. `@online` entries are kept. Entries the parser drops and duplicate keys are reported as warnings; a non-UTF-8 file is decoded as Latin-1 with a warning. The original `.bib` file is not modified.
2. Reconcile citation keys. First, every key whose identity changed (a corrected DOI, swapped or rotated keys) releases its filenames: bytes another key of the old publication still has are dropped from that name, everything else moves to `papers/_unreferenced/` and SQLite follows the move. Keys removed from the BibTeX file release their names only when their publication is still cited under another key; otherwise they are left alone, because the user may have passed only some of their `.bib` files. Then a renamed key that still points at the same DOI, arXiv id, or URL keeps the downloaded bytes and the file is renamed. A second key for the same identity gets its own filename, hard-linked to the stored bytes when possible. A publication whose file sits in `_unreferenced/` is moved back under the key that cites it. If `{citation_key}.pdf` already holds bytes from another publication or an unmanaged file, the key gets `{citation_key}--{hash}.pdf` instead.

   Filenames are the NFC-normalized key with letters and digits of any script kept and everything else replaced by `_`, capped at 120 UTF-8 bytes.
3. Discover a PDF from an explicit `.pdf` URL, then OpenAlex, then `https://arxiv.org/pdf/{id}`. A PVLDB paper (DOI prefix `10.14778/` or that journal name) with a volume is first looked up on its vldb.org volume page, by title with the start page as tie-breaker, because vldb.org names files after its own first author. Papers missing from older volume pages are tried at `p{page}-{first author}.pdf` after a HEAD request confirms a PDF is there. A USENIX paper (ATC, FAST, NSDI, OSDI) takes the `citation_pdf_url` of its usenix.org page. The entry's `url` names that page, or the paper is found by title in the program at `/conference/{short name}{yy}/technical-sessions`. A CIDR paper is found by title in `cidr{year}/program.html` on cidrdb.org, including the frame that older programs use. Over the years that program has given the title as the link itself, as text followed by a "PDF" link, or as text after an icon link, so each layout pairs titles with links differently. Only PDFs on cidrdb.org or under vldb.org/cidrdb/ count. A VLDB conference paper (venue naming VLDB or Very Large Data Bases but not a journal) up to 2007 is looked up in `vldb.org/conf/{year}/`. That page is an Apache index in most years, a frame around a table of contents in 2007, and an index with only a `papers/` subdirectory in 2005, so frames and subdirectories are read when the page itself lists no PDF. A link whose text is the title wins. Otherwise the file named after the start page (`P169.pdf`, `p553-stonebraker.pdf`) is taken, unless the numbers in the file names grow by less than two per file, which means they count papers, as in 1999, rather than pages. An OpenProceedings DOI (`10.5441/002/`, `10.48786/`) resolves directly to the PDF, so `https://doi.org/{doi}` is the candidate. Any of these matches skips OpenAlex. Found links are cached. Title search is used only when no DOI, arXiv id, or direct PDF exists, and only when the OpenAlex title and year are a close match. That match does not change the stored identity.
4. Download over HTTP(S). `file:`, localhost, private addresses, and host names that resolve to private addresses are refused, including after redirects. The address is checked when the request is made; a resolver that answers differently a moment later at connect time (DNS rebinding) is not covered. The response must be a PDF that PyMuPDF can open. HTML login pages and HTTP 401 are `authentication_required`, a Cloudflare bot check (`cf-mitigated: challenge`) is `manual_action_required`, any other 403 is `access_denied`, 404 is `not_found`. 429, 5xx, and timeouts are retried with backoff. BibVault never imitates a browser to pass a bot check.
5. Write one PDF per paper to `{citation_key}.pdf`: candidates are tried best first (the entry's own PDF link, then published, accepted, preprint) and the first that downloads is kept; the rest are not requested. A paper whose `{citation_key}.pdf` is present is skipped before resolution, so later runs neither look it up nor download another version of it. An existing file is not replaced, even if the user edited it. A file that was deleted is forgotten and downloaded again, which is how the user trades a preprint for a published copy. Libraries from before this rule may still hold `.published.pdf`, `.preprint.pdf`, or `.accepted.pdf` files; they are read but no longer written.
6. With `--browser`, a web page whose HTTP HTML has no main text is rendered once in Crawl4AI's ordinary headless Chromium, then the rendered HTML is passed to Trafilatura. Stealth, undetected-browser, and `magic` modes are disabled. Papers still missing after the steps above that only a real browser can reach are handled in a second pass. Cloudflare sends a browser under automation (Playwright, remote debugging) into an endless check even after a human ticks it, so BibVault drives nothing for ACM: it launches an installed Chromium-family browser with `--user-data-dir` pointing at its own profile, whose download folder and "always download PDFs" settings it writes before every launch, with sync turned off (`--disable-sync`) so an account the browser signs in to cannot replace them. Every link goes to the browser binary itself, which hands it to the instance already running on that profile; `open -a` cannot be used, because macOS drops `--args` for a running app and sends a bare URL to whichever instance it picks, often the user's own profile. On macOS, BibVault notes the frontmost app (`lsappinfo front`) before opening a PDF link and, once the browser takes the front, reactivates that app with `open -b`; it skips this when the user was in the same browser, since two instances share a bundle id. It opens `https://dl.acm.org/doi/pdf/{doi}?download=true`, waits for a new `.pdf` in that folder, checks it is a PDF whose first page carries the title, and stores it. A file that fails the title check stays in the folder. Two links in a row that save nothing end the pass, since that usually means the window is waiting for the user. Before any PDF of a publisher group is opened, BibVault opens that group's sign-in page (ACM's home, or the library portal derived from the proxy host) and waits for the user to press Enter in the terminal. IEEE (`10.1109/`) and Springer (`10.1007/`) share the library group and join the pass once `[browser.proxy_hosts]` has any entry, since one proxy host gives the portal. The proxy changes these host names over time, so at the library sign-in the user is asked for each publisher's current address from the portal. A pasted host replaces the configured one and, when it differs, is written into the user's config with tomlkit so comments and other settings stay; Enter keeps the configured host. A publisher left with no host is not opened, because off the proxy it shows only its paywall; its papers end as `manual_action_required` and, when deferred, take the preprint. After sign-in the user closes the browser window; BibVault reads session cookies from the profile and downloads those PDFs over HTTP with a browser User-Agent. If the cookie store cannot be unlocked, it falls back to opening links in the browser. A silent download that returns a login page is an authentication failure for that publisher: the paper stays `authentication_required`, later papers of the same publisher are not tried, and no preprint is taken for them, so the next `--browser` run can try the publisher again after a fresh sign-in. The other library publisher is still tried. The link is the publisher's PDF address with that host swapped in: `/stampPDF/getPDF.jsp?tp=&arnumber={n}` for IEEE and `/content/pdf/{doi}.pdf` for Springer. IEEE's document number comes from the `Location` that doi.org answers for the DOI, and it is cached. BibVault holds no school credentials. The file records which publisher it came from. For papers this pass can open, the HTTP pass takes only a published copy (or the entry's own PDF link) and holds other versions back; after the browser has tried such a paper and failed, the HTTP candidates are tried again with preprints allowed, reusing the run's OpenAlex answers. A held-back paper the browser did not reach stays missing (`manual_action_required`) so the next `--browser` run tries the publisher first; so do the papers of a run of two or more links that saved nothing, since that points at the window rather than at those papers. Progress for the whole run is one `Fetching` line. A browser sign-in prompt is printed under that line. The default text report is slim (already on disk, newly downloaded, problems only); `--format json` still lists every entry.

## Status when nothing new was stored

In order: a present preferred file is `already_exists`; then a login page or 401 is `authentication_required`; a bot check is `manual_action_required`; 403 is `access_denied`; 429 is `rate_limited`; other download errors are `failed`; a 404 is `not_found`. The reported error is the one from the download that decided the status. Without any download attempt, an OpenAlex outage is `failed` (`rate_limited` for 429), an open-access landing page without a PDF is `manual_action_required`, a known work without an open-access copy in OpenAlex is `no_open_access_found` (the fix is `bibvault import`), and anything else is `not_found`. A web entry (`@online`, `@misc`, `@software`, `@dataset`, `@electronic`, `@www`, `@webpage`) with no DOI, arXiv id, or PDF link is fetched by Crawl4AI's HTTP strategy and saved as `papers/{citation_key}.md`. Crawl4AI's cache and deep crawling are disabled. Trafilatura (`favor_recall`, with images, links, tables, and metadata) is the sole authoritative extractor and receives Crawl4AI's original or browser-rendered HTML; Crawl4AI's own Markdown is ignored. The file provider is `crawl4ai+trafilatura`. Image URLs are not downloaded, and the HTML response is not stored. A page that yields no main text is `failed`. An entry of those types with no URL is `not_found` and makes no request. A Markdown file already on disk is skipped, the same way a PDF is.

`bibvault import` accepts validated PDFs and non-empty UTF-8 Markdown files. Imported files have version `provided`; optional source URL and provider arguments are stored with the same provenance fields as downloaded content.

## Not in V0.1

- Publisher authentication and paywalled downloads
- Shared library across projects
- MCP

OpenAlex is the metadata source. Crossref and Unpaywall are not called yet. An API key (`BIBVAULT_OPENALEX_API_KEY`, or `resolution.openalex_api_key` in a config file) is sent as an `Authorization: Bearer` header rather than `?api_key=`, because request URLs appear in the logs. `bibvault auth login openalex` reads the key without echo, checks it against `/rate-limit`, and writes it to `~/.config/bibvault/credentials.toml` with mode 0600; that file sits between the user config and the project config in precedence. The key doubles as the user's openalex.org login, so it is never printed beyond its last four characters. A resolution that already found a published PDF is cached in SQLite; a preprint-only result is queried again while the paper is still missing. Title searches are billed against the daily budget, so each result, found or not, is reused for seven days.

Without a key, an IP address shares one small daily budget with anonymous visitors of openalex.org; spending it makes the website show its "you're a bot" page. A 429 with `X-RateLimit-Remaining` above zero is the per-second limit and is retried after a short wait. Any other 429 means the budget is spent: the rest of the run makes no OpenAlex request, and SQLite records the reset time from `X-RateLimit-Reset` (midnight UTC if absent) together with a hash prefix of the key, so later runs skip OpenAlex until then unless a different key is configured. A 401 (key rejected) likewise ends OpenAlex requests for the run.

Without a key BibVault also limits itself, so that it never becomes the reason the user's browser is turned away: at most `KEYLESS_DAILY_REQUESTS` (100) OpenAlex requests per UTC day, counted in SQLite before each request, and no title search, which costs ten lookups. The first of these in a run logs one warning that explains the limits and how to add a key.
